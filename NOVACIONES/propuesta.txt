================================================================================
  NOTAS GENERALES DE POWERAPPS (importantes para la migración)
================================================================================
  - El separador ";" en PowerApps es separador de argumentos (config regional);
    en notación estándar equivale a ",".
  - ".Text" SIEMPRE devuelve string. Por eso usan Value(...) para convertir a
    número antes de operar.
  - Coalesce(x; 0)  =  "si x es null/vacío -> 0".
  - Text(numero; "[$-en-US]#,###")  =  entero (sin decimales) + separador de
    miles. (El campo 4 usa "#,##0", mismo efecto entero.)

  *** REGLA DE REDONDEO (definida por negocio) ***
  - El valor final de cada campo se trunca al ENTERO MÁS CERCANO HACIA ABAJO
    (piso / floor). En JS: Math.floor(valor).
  - OJO: esto DIFIERE del comportamiento literal de PowerApps, donde "#,###"
    redondea al entero más cercano. La regla de negocio (floor) MANDA sobre el
    comportamiento original de PowerApps.
  - Para valores negativos, floor va hacia abajo (ej. -2.3 -> -3). La mayoría
    de los campos son positivos, así que floor = truncar decimales.
  - LookUp(tabla; condicion; columna)  =  busca la PRIMERA fila que cumple la
    condicion y devuelve la columna indicada (o el registro completo si no se
    indica columna).

================================================================================
  ******  VALIDADOR: "REQUIERE HONORARIOS"  ******
================================================================================
  El campo "requiere honorarios" SE CONVIERTE EN VALIDADOR EXACTAMENTE EN EL
  CÁLCULO DE LA TASA GXC (Campo 2).

  REGLA DE NEGOCIO:
      - Cuando SÍ hay HONORARIOS  -> se ANULAN los gastos de cobranza (GxC = 0)
                                     y se aplica OTRO CÁLCULO (el de honorarios).
      - Cuando NO hay honorarios (opción "NO, COBRANZAS - Call int.ext tabla
        GXC") -> se usan los GASTOS DE COBRANZA de la tabla.
      Es decir: HONORARIOS y COBRANZA son EXCLUYENTES (nunca los dos a la vez).

  Momento / condición en que valida (Campo 2):

      SI  requiere_honorarios.Selected.Value
              == "NO, COBRANZAS - Call int.ext tabla GXC"   (NO hay honorarios)
          ENTONCES  -> se HABILITA la búsqueda en la tabla
                       SimiladorDNC_Lappiz_rangosGastosCobranza y se calcula
                       la TASA GXC real (PorcTasaGastoCobranza * 100).
      SINO (SÍ hay honorarios)
          ENTONCES  -> TASA GXC = 0  (cobranza anulada)
                    -> y se aplica el CÁLCULO DE HONORARIOS (ver PENDIENTE).

  Efecto en cascada (por qué es tan delicado):
      - Si hay honorarios -> tasa_GxC = 0.
      - Con tasa_GxC = 0:
            * Campo 4 (gastos gxc):  el valor calculado base se vuelve 0
              (luego se clampa contra TOPE_MINIMO; ojo: si TOPE_MINIMO > 0 el
              resultado NO queda en 0 sino en TOPE_MINIMO -> REVISAR si en caso
              de honorarios el GxC debe forzarse a 0 explícitamente).
            * Campo 8 (pago negociacion): el bloque GxC devuelve 0, por lo que
              pago_negociacion = abono_minimo solamente.
      - Es decir, "requiere honorarios" actúa como INTERRUPTOR: enciende
        COBRANZA o enciende HONORARIOS, nunca ambos.

  IMPORTANTE: la comparación es contra el TEXTO EXACTO
      "NO, COBRANZAS - Call int.ext tabla GXC"
  Cualquier diferencia (mayúsculas, espacios, tildes) rompe la validación.

  PENDIENTE: falta el código fuente del CÁLCULO DE HONORARIOS (la rama "SÍ hay
  honorarios"). En el PowerApps actual esa rama solo pone tasa_GxC = 0; el
  cálculo alterno de honorarios debe estar en otro campo/control aún no
  entregado.

================================================================================
  CAMPO 1)  ABONO MÍNIMO REQUERIDO
================================================================================
  VARIABLES NECESARIAS:
    var_BaseAbono   = PORCENTAJE_ABONO_MINIMO (dropdown edad_mora)
                      * pago_minimo
    var_TasaGxC     = tasa_GxC / 100          (declarada, NO se usa)
    var_TopeMinimo  = TOPE_MINIMO  (dropdown) (declarada, NO se usa)
    var_TopeMaximo  = TOPE_MAXIMO  (dropdown) (declarada, NO se usa)

  FÓRMULA A APLICAR:
    abono_minimo_requerido = var_BaseAbono

  OBSERVACIÓN:
    En el código fuente, todo el bloque de GxC con Min/Max/Topes está
    COMENTADO (/* ... */). Por lo tanto, en la práctica el campo es ÚNICAMENTE:
        PORCENTAJE_ABONO_MINIMO * pago_minimo

================================================================================
  CAMPO 2)  TASA GXC   (aquí valida "requiere honorarios")
================================================================================
  VARIABLES / FUENTES:
    requiere_honorarios = dropdown (VALIDADOR, ver arriba)
    edad_mora           = dropdown edad_mora (EDAD_MORA seleccionada)
    tabla               = SimiladorDNC_Lappiz_rangosGastosCobranza
                          (PowerApps original: rangos_gastos_cobranzas)
    TASA_GASTO_COBRANZAS = columna de la tabla, buscada por EDAD_MORA

  FÓRMULA A APLICAR:
    SI requiere_honorarios == "NO, COBRANZAS - Call int.ext tabla GXC"
        tasa_GxC = LookUp(tabla; EDAD_MORA == edad_mora_sel; TASA_GASTO_COBRANZAS) * 100
    SINO
        tasa_GxC = 0

  OBSERVACIÓN (confirmado con la tabla real):
    En SimiladorDNC_Lappiz_rangosGastosCobranza la columna PorcTasaGastoCobranza
    viene como FRACCIÓN (ej. 0.0714, 0.0952, 0.1428).
    -> POR LO TANTO SÍ SE MULTIPLICA POR 100 para obtener el porcentaje
       (0.0714 -> 7.14 %).
    Valores reales por rango:
        1 - 10 Dias    -> 0       (Tope_Min 0,     Tope_Max 0)
        11 - 15 Dias   -> 0.0714  (Tope_Min 11900, Tope_Max 309400)
        16 - 30 Dias   -> 0.0952  (Tope_Min 11900, Tope_Max 309400)
        31 - 60 Dias   -> 0.1071  (Tope_Min 14280, Tope_Max 309400)
        61 - 90 Dias   -> 0.119   (Tope_Min 17850, Tope_Max 309400)
        91 - 120 Dias  -> 0.1428  (Tope_Min 17850, Tope_Max 309400)
        121 - 150 Dias -> 0.1428  (Tope_Min 17850, Tope_Max 309400)
        Mayor de 150   -> 0.1428  (Tope_Min 17850, Tope_Max 309400)
    Nombres reales de columnas en la tabla:
        EdadMoragxc          (= EDAD_MORA)
        PorcTasaGastoCobranza(= TASA_GASTO_COBRANZAS)
        Tope_Minimo, Tope_Maximo
        PorcAbonoMinimo      (= PORCENTAJE_ABONO_MINIMO, también fracción: 0.1,
                              0.05, 0.03)
        MinDias, MaxDias     (rango de días para ubicar la edad de mora)

================================================================================
  CAMPO 3)  1ER MES FACTURACIÓN (valor)
================================================================================
  VARIABLES NECESARIAS:
    var_BaseAbono     = saldo_total - abono_minimo
    var_TasaVigente   = tasa / 100
    var_GastoCobranza = gastos_cobranza
    var_Total_iCS     = (interes_corriente + interes_extracontable
                         + interes_mora + otros_cargos) / 6

  FÓRMULA A APLICAR:
    fact_mes1 = (var_BaseAbono * var_TasaVigente)
              + var_Total_iCS
              + var_GastoCobranza

  OBSERVACIÓN:
    El "/6" reparte intereses y otros cargos en 6 cuotas.
    El mes 1 SÍ incluye el gasto de cobranza.

================================================================================
  CAMPO 4)  GASTOS POR COBRANZA (GxC)   *** MUY DELICADO ***
================================================================================
  VARIABLES NECESARIAS:
    _valorCalculado = (pago_minimo - abono_minimo) * (tasa_GxC / 100)
    _registroRango  = LookUp(tabla; EDAD_MORA == edad_mora_sel)
                      -> de aquí salen TOPE_MAXIMO y TOPE_MINIMO

  FÓRMULA A APLICAR (clamp entre topes):
    SI   (TOPE_MAXIMO > 0  Y  _valorCalculado > TOPE_MAXIMO)
         gastos_gxc = TOPE_MAXIMO
    SINO SI (_valorCalculado < TOPE_MINIMO)
         gastos_gxc = TOPE_MINIMO
    SINO
         gastos_gxc = _valorCalculado

  OBSERVACIONES:
    - El TOPE_MAXIMO solo aplica si TOPE_MAXIMO > 0 (si es 0, no hay techo).
    - Existe una versión COMENTADA arriba (sin topes); la válida es ESTA con
      topes.
    - Formato de salida "#,##0" (entero, igual que los demás en la práctica).
    - La BASE de cálculo aquí es (pago_minimo - abono_minimo).  <-- comparar
      con Campo 8, que usa OTRA base.

================================================================================
  CAMPO 5)  2 A 6 MES FACTURACIÓN (valor)
================================================================================
  VARIABLES NECESARIAS:
    var_BaseAbono     = saldo_total - abono_minimo
    var_TasaVigente   = tasa / 100
    var_PlazoNov      = plazo_novacion ('Plazo Novación' del dropdown)
    var_GastoCobranza = gastos_cobranza          (declarada, NO se usa)
    var_Total_iCS     = (interes_corriente + interes_extracontable
                         + interes_mora + otros_cargos) / 6

  FÓRMULA A APLICAR:
    fact_mes_2a6 = (var_BaseAbono / var_PlazoNov)
                 + ((var_BaseAbono * var_TasaVigente) + var_Total_iCS)

  DIFERENCIAS CLAVE vs CAMPO 3 (mes 1):
    - Meses 2 a 6 SÍ incluyen abono a capital: (var_BaseAbono / var_PlazoNov).
      El mes 1 NO divide por plazo.
    - Meses 2 a 6 NO suman el gasto de cobranza (var_GastoCobranza se declara
      pero no se usa). El mes 1 SÍ lo suma.
    - El interés es PLANO sobre var_BaseAbono completo (no decreciente / no
      amortización francesa) en ambos casos.

================================================================================
  CAMPO 6)  CUOTA ESTIMADA
================================================================================
  VARIABLES NECESARIAS:
    var_BaseAbono     = saldo_total - abono_minimo
    var_TasaVigente   = tasa / 100
    var_PlazoNov      = plazo_novacion ('Plazo Novación' del dropdown)
    var_GastoCobranza = gastos_cobranza          (declarada, NO se usa)

  FÓRMULA A APLICAR:
    cuota_estimada = (var_BaseAbono / var_PlazoNov)
                   + ( (var_BaseAbono - ((var_BaseAbono / var_PlazoNov) * 6))
                       * var_TasaVigente )

  INTERPRETACIÓN:
    - 1er término: cuota de capital (base / plazo).
    - 2do término: interés sobre el saldo restante DESPUÉS de 6 cuotas de
      capital.

================================================================================
  CAMPO 7)  SALDO FINAL A DIFERIR
================================================================================
  VARIABLES NECESARIAS:
    var_BaseAbono   = saldo_total - abono_minimo
    var_TasaVigente = tasa / 100                 (declarada, NO se usa)
    var_GastoCobranza = gastos_cobranza          (declarada, NO se usa)
    var_Total_iCS   = (interes_corriente + interes_extracontable
                       + interes_mora + otros_cargos) / 6   (declarada, NO se usa)

  FÓRMULA A APLICAR:
    saldo_final_a_diferir = var_BaseAbono

  OBSERVACIÓN:
    El campo es simplemente (saldo_total - abono_minimo). Las demás variables
    se declaran pero no se usan en el resultado.

================================================================================
  CAMPO 8)  PAGO PARA LA NEGOCIACIÓN
================================================================================
  VARIABLES NECESARIAS:
    var_AbonoMin    = abono_minimo
    var_TasaGxC     = tasa_GxC / 100
    var_TopeMinimo  = TOPE_MINIMO (dropdown edad_mora)
    var_TopeMaximo  = TOPE_MAXIMO (dropdown edad_mora)
    (var_BaseAbono, var_TasaVigente, var_GastoCobranza, var_Total_iCS se
     declaran pero NO se usan)

  FÓRMULA A APLICAR:
    gxc = SI (var_TasaGxC <= 0)
              0
          SINO
              Min( Max(var_AbonoMin * var_TasaGxC ; var_TopeMinimo) ; var_TopeMaximo )

    pago_negociacion = var_AbonoMin + gxc

  OBSERVACIÓN / INCONSISTENCIA A CONFIRMAR CON NEGOCIO:
    *** ESTA ES LA INCONSISTENCIA PRINCIPAL ***
    - Campo 4 (gastos por cobranza): GxC sobre base (pago_minimo - abono_minimo).
    - Campo 8 (este):                GxC sobre base (abono_minimo).
    -> BASES DISTINTAS para el MISMO concepto (GxC).
    - Además, el Campo 8 TIENE disponible el valor ya calculado del Campo 4
      (var_GastoCobranza), lo declara... y lo IGNORA para RECALCULAR el GxC con
      otra fórmula y otra base.
    - Lo esperable / limpio sería:
          pago_negociacion = abono_minimo + gastos_cobranza   (el del Campo 4)
      pero el código hace:
          pago_negociacion = abono_minimo + (GxC recalculado sobre abono_minimo)
    -> Posible BUG heredado de PowerApps. CONFIRMAR con negocio cuál base es la
       correcta antes de codear en JS.

================================================================================

      6 (cuota_estimada)  ->  8 (pago_negociacion)

  Diagrama:
      INPUTS crudos
         |
         +-> tasa_GxC (C2) ----------------+

         |        |                        |
         |        +-----------------------+--> pago_negociacion (C8)
         |                                 |
         +-> saldo_final_diferir (C7)      |
         |                                 |

                                           +--> cuota_estimada (C6)
